# VARTA: Zero-budget growth plan

This plan prioritizes real community participation over vanity metrics. It does not promise search rankings, virality, or a specific number of users.

## North-star measure

**Weekly returning contributors:** people who make a meaningful contribution (a post, reply, guide suggestion, or correction) and return in a later week.

Track registrations alongside active contributors, replies per discussion, repeat visits, and which knowledge topics prompt useful conversations. Do not treat page views or GitHub stars as proof of a healthy community.

## Days 1–3: reliability and discoverability

- [ ] Confirm the latest GitHub Pages deployment and check `/robots.txt` and `/sitemap.xml` in a browser.
- [ ] Complete real-user checks for signup, email verification if enabled, sign-in, password reset, sign-out, profile save, post creation, reply, like, follow, notifications, reporting, and moderator access.
- [ ] Verify mobile navigation, headings, readable text, keyboard focus, and useful error messages.
- [ ] In Google Search Console, verify the URL-prefix property `https://ashubagri.github.io/Varta/` and submit `sitemap.xml`. Inspect indexing errors; submission is not a guarantee of indexing.
- [ ] Add relevant GitHub repository topics through the repository About settings.

## Days 4–10: establish a recognizable reason to visit

Publish one thoughtful prompt per day and rotate through these five themes:
1. Science & Technology — explain a claim and link to a credible source.
2. Indian Knowledge — discuss texts, history, context, and interpretation respectfully.
3. Sound & NADA — connect music practice with careful explanations of acoustics and research.
4. Culture & Nature — discuss heritage, biodiversity, and living traditions.
5. World Affairs — discuss a current issue using multiple credible sources.

Each prompt should contain a clear question, short context, links when relevant, and an invitation to respond. Label opinion, tradition, and scientific evidence distinctly.

## Days 11–20: invite the first community

- Share one useful, specific VARTA link—not just the homepage—where the topic is relevant and promotion is permitted.
- Invite people personally who genuinely care about the subject. Ask them to contribute one question, reply, or correction.
- Use existing YouTube/community channels to introduce VARTA without spamming unrelated audiences.
- Welcome contributors, reply to their contributions, and promptly handle abuse reports.
- Never buy followers, fake engagement, scrape contact lists, or mass-post promotional links.

## Days 21–30: learn and improve

Review weekly:
- New registrations and the percentage that complete their first contribution.
- Number of members who contribute and return the following week.
- Posts with meaningful replies, not just likes.
- Search Console impressions, clicks, and indexing issues.
- Reports, spam, and unresolved user problems.

Keep what drives meaningful repeat participation. Improve the biggest barrier before adding more features.

## Free tools

- GitHub Issues for reproducible bugs and feature requests.
- Google Search Console for indexing and search performance.
- A simple spreadsheet for weekly growth metrics.
- Existing VARTA pages and existing social/video channels for relevant sharing.

## Monetization gate

Do not add intrusive ads or paid features before there is consistent genuine participation. Once a real audience exists, test transparent sponsorships, optional supporter contributions, educational events, or other relevant offers. Never sell member data or make moderation dependent on payment.

## Limits and dependencies

- Search engines decide when and whether to index pages; a sitemap is a discovery hint, not a guarantee.
- Search Console verification and sitemap submission require the site owner's action.
- The plan requires manual testing with separate user roles and real devices. A successful deployment does not prove every feature works.
- Do not publish private credentials, service-role keys, user emails, or private report contents in repository files.
